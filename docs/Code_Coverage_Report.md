## 3. Module-by-Module Coverage Analysis

### 3.1 Authentication Component (`src/auth.py` – 98% Coverage)
- **Covered Logic**: Valid campus SSO token authentication, session cookie issuance, 30-minute idle session invalidation, manual logout, 5-attempt brute-force lockout window (15 minutes), unknown user handling, and role extraction.
- **Uncovered Lines**: Line 146 is a defensive fallback return branch for malformed token payloads.

### 3.2 Reservation Manager Component (`src/reservation_manager.py` – 95% Coverage)
- **Covered Logic**: Placing holds on CheckedOut titles, queue position assignment, rejection of Available titles, duplicate active hold prevention, active hold limit enforcement (max 5), member hold listing, cancellation with ownership validation, title return with automatic hold promotion to Ready, 72-hour pickup window enforcement, and demand report aggregation.
- **Uncovered Lines**: Defensive null checks for edge cases where database returns an unexpected empty tuple during cascade promotion.

### 3.3 Security & Input Sanitization (`src/security.py` – 94% Coverage)
- **Covered Logic**: Sliding-window rate limiter (60 req/min), client IP isolation, window reset, ISBN-10/13 regex validation with checksum and X-suffix support, SQL meta-character stripping, HTML tag stripping (XSS prevention), and password leakage detection in logs.

### 3.4 Notification Component (`src/notification.py` – 93% Coverage)
- **Covered Logic**: Hold-ready email templating (72-hour notice), 24-hour expiration reminder email, 3-attempt exponential backoff retry mechanism, and delivery failure logging to the audit trail.

### 3.5 Catalog Search Component (`src/catalog_search.py` – 91% Coverage)
- **Covered Logic**: Search by ISBN, partial title, and author; all-fields compound search; pagination controls (10/page); book detail lookup with hold eligibility; empty query rejection; malformed ISBN rejection; and zero-match advice.

### 3.6 Fine Management Component (`src/fine_manager.py` – 90% Coverage)
- **Covered Logic**: Overdue fine assessment (\$1.00/day), member fine listing, Campus Wallet and UPI settlement, receipt generation with `TXN-` ID, balance clearance, hold blocking when unpaid fines exceed \$20 threshold, and unauthorized settlement prevention.

### 3.7 Librarian Administration (`src/admin.py` – 86% Coverage)
- **Covered Logic**: Return processing and hold advancement, demand report retrieval, new book registration, metadata editing, and strict RBAC verification returning 403 Forbidden for Student tokens.

### 3.8 Flask Web & API Gateway (`src/app.py` – 83% Coverage)
- **Covered Logic**: All REST API endpoints (`/api/v1/books`, `/api/v1/holds`, `/api/v1/titles/return`, `/api/v1/fines`, `/health`), security header injections, rate limiting middleware, session cookie setting, UI home page, book detail, my-holds view, fines desk view, librarian dashboard, login, and logout.
- **Uncovered Lines**: CLI launch block (`if __name__ == '__main__': app.run()`).

### 3.9 Database Layer (`src/database.py` – 67% Coverage)
- **Covered Logic**: Schema DDL execution, table creation, index creation, initial data seeding for titles, members, fines, and initial holds, parameterized query helpers.
- **Uncovered Lines**: Auxiliary database methods for alternative non-memory disk-path instantiation.
